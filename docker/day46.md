# День 46 — GitHub Actions: Token Permissions

## Цель дня

Изучить управление правами GITHUB_TOKEN на уровне
workflow и отдельных jobs, освоить принцип
минимально необходимых привилегий.

### Практика 1. Проверка существующего workflow

Проверена текущая конфигурация first-ci.yml.
Установлено отсутствие явно заданных permissions.

```bash
head -n 50 .github/workflows/first-ci.yml # Просмотр конфигурации
grep -n -A 8 'permissions:' .github/workflows/first-ci.yml # Поиск настроек прав
```

### Практика 2. Настройка permissions на уровне workflow

Добавлено глобальное ограничение прав GITHUB_TOKEN.

```yaml
permissions:
  contents: read
```

Токену предоставлено разрешение на чтение содержимого
репозитория без права записи.

### Практика 3. Проверка прав в GitHub Actions

Изменения отправлены на GitHub.
Проверен запуск workflow #79.

В разделе Set up job подтверждены разрешения:

- Contents: read
- Metadata: read

Workflow завершился успешно.

### Практика 4. Настройка permissions на уровне job

Для задания matrix-check установлено дополнительное
ограничение прав токена.

```yaml
permissions: {}
```

Настройка переопределяет глобальные разрешения
для конкретного задания.

### Практика 5. Итоговая проверка CI

Проверен запуск workflow #80.

В задании matrix-check (testing, 3.11)
подтверждено наличие только Metadata: read.

Разрешение Contents: read отсутствует.
Все три задания матрицы завершились успешно.
Workflow сохранил работоспособность.

## Итог дня

- Изучено назначение GITHUB_TOKEN.

- Настроены права на уровне job.

- Проверена работоспособность CI после ограничения прав.
