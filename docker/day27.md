# День 27 — GitHub Actions: условное выполнение шагов CI

## Цель
Научиться управлять выполнением шагов GitHub Actions в зависимости от результата CI, проверять обработку ошибок и восстанавливать успешную работу pipeline.

### Практика 1. Проверка существующего workflow
- Проверили состояние репозитория Git.
- Изучили `.github/workflows/first-ci.yml`.
- Проверили существующие шаги CI: Checkout, Check environment, Check Docker, Validate Docker Compose и Verify CI recovery.
- Убедились, что предыдущий pipeline работает успешно.

### Практика 2. Добавление условных шагов
- Добавили шаг `Report success` с условием `if: success()`.
- Добавили шаг `Report failure` с условием `if: failure()`.
- Проверили изменения через `git diff` и `git diff --check`.
- Сохранили изменения в Git и отправили на GitHub.

### Практика 3. Проверка успешного сценария
- Запустили обновлённый GitHub Actions workflow.
- Убедились, что pipeline завершился успешно.
- `Report success` выполнился.
- `Report failure` был пропущен.
- Подтвердили корректность условного выполнения шагов.

### Практика 4. Проверка обработки ошибки
- Изменили `exit 0` на `exit 1` в шаге `Verify CI recovery`.
- Создали коммит `987a6da` и отправили его в GitHub.
- GitHub Actions, запуск №8, завершился с ошибкой.
- `Verify CI recovery` завершился с кодом 1.
- `Report success` был пропущен.
- `Report failure` выполнился успешно.
- Убедились, что CI правильно реагирует на ошибку.

### Практика 5. Восстановление успешного CI
- Вернули `exit 0` в `Verify CI recovery`.
- Проверили изменения через `git diff --check` и `git diff`.
- Создали коммит `8b24912` и отправили его в GitHub.
- GitHub Actions, запуск №9, завершился успешно за 12 секунд.
- `Report success` выполнился, `Report failure` был пропущен.

### Практика 6. Итоговая проверка
- Проверили `git status` и последние коммиты.
- Подтвердили синхронизацию `main` и `origin/main`.
- Проверили итоговую конфигурацию условных шагов.
- Убедились, что рабочая директория чистая.

## Изменённые и созданные файлы
- `.github/workflows/first-ci.yml` — добавлены условные шаги и проверена обработка ошибок.
- `docker/day27.md` — журнал обучения.

## Итог дня
Освоили условное выполнение шагов GitHub Actions с помощью `success()` и `failure()`. На практике проверили успешный и аварийный сценарии CI, научились диагностировать отказ pipeline и восстанавливать его работу.

**Результат:** CI работает успешно, обработка ошибок проверена, изменения сохранены в GitHub.
