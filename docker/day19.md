# День 19 — Docker Compose: переменные окружения

## Цель

Изучить управление переменными окружения в Docker Compose, работу с `.env`, `env_file` и `environment`, порядок приоритета настроек, применение изменений и базовую защиту конфигурационных файлов.

## Практика 1. Проверка окружения

- Проверены Docker Engine 29.8.1 и Docker Compose 5.5.1.
- Проверено отсутствие запущенных контейнеров.
- Проверено, что порт 8085 свободен.

## Практика 2. Подготовка проекта

- Создан каталог `~/docker-lab/day19-compose`.
- Подготовлены каталоги `backend` и `nginx`.
- Использованы Dockerfile и конфигурация Nginx из проекта предыдущего дня.

## Практика 3. Создание `.env`

- Создан файл `.env`.
- Определены `COMPOSE_PROJECT_NAME`, `NGINX_PORT` и `APP_MESSAGE`.
- Проверено содержимое файла.

## Практика 4. Подстановка переменных в Docker Compose

- Настроен `compose.yaml`.
- Подключены переменные из `.env`.
- Проверена итоговая конфигурация через `docker compose config`.
- Собран и запущен проект с backend и Nginx на порту 8085.

## Практика 5. Использование `env_file`

- Создан файл `backend/backend.env`.
- Добавлены `APP_ENV`, `APP_LOG_LEVEL` и `APP_DEBUG`.
- Настроена передача переменных в backend.
- Проверен приоритет `environment` над `env_file`.
- Backend пересоздан, значения подтверждены через `docker inspect`.

## Практика 6. Проверка приложения

- Проверено состояние контейнеров через `docker compose ps`.
- Выполнен HTTP-запрос через Nginx.
- Получен ответ `200 OK` и текст `Hello from Day 19 Environment`.

## Практика 7. Изменение `.env`

- Изменено значение `APP_MESSAGE`.
- Подтверждено, что изменение `.env` не обновляет уже работающий контейнер.
- Backend пересоздан с новой конфигурацией.
- Проверены новое значение переменной и HTTP-ответ `Hello from Updated Environment`.

## Практика 8. Безопасность файлов окружения

- Проверена доступность переменных через `docker inspect`.
- Проверены права файлов `.env` и `backend/backend.env`.
- Права изменены с `644` на `600`.
- Установлено, что обычные переменные окружения не являются защищённым хранилищем секретов.

## Практика 9. Приоритет переменных

- Временно удалено переопределение `APP_ENV` из `environment`.
- Подтверждено получение `APP_ENV=staging` из `env_file`.
- Восстановлено `APP_ENV=development`.
- Проверены итоговая конфигурация и фактическое окружение контейнера.

## Практика 10. Одноразовые контейнеры

- Изучена команда `docker compose run`.
- Выполнена разовая команда через `--entrypoint /bin/echo`.
- Получен ответ `One-time container OK`.
- Подтверждено, что основные сервисы продолжили работу.

## Созданные файлы

- `~/docker-lab/day19-compose/compose.yaml`
- `~/docker-lab/day19-compose/backend/backend.env`

- `~/docker-lab/day19-compose/nginx/default.conf`
- `~/devops-learning/docker/day19.md`

## Итог дня

Освоены переменные окружения Docker Compose, различия между `.env` и `env_file`, приоритет `environment`, применение конфигурационных изменений, ограничение доступа к файлам и запуск одноразовых контейнеров.

**Результат:** приложение успешно работает через Nginx на порту 8085. Финальная проверка конфигурации прошла без ошибок, оба контейнера запущены, HTTP-ответ — `200 OK`.
