
# День 34 — GitHub Actions: ручной запуск с параметрами

## Цель
Научиться передавать параметры в GitHub Actions через workflow_dispatch и выбирать целевое окружение при ручном запуске CI.

### Практика 1. Проверка существующего workflow
- Проверен `.github/workflows/first-ci.yml`.
- Подтверждена работа автоматического запуска через push и ручного запуска через workflow_dispatch.

### Практика 2. Добавление параметра ручного запуска
- Добавлен input `target_environment`.
- Тип параметра: `choice`.
- Доступные значения: `testing` и `staging`.
- Значение по умолчанию: `testing`.

### Практика 3. Передача параметра в job
- В шаг `Check environment` добавлена переменная `TARGET_ENV`.
- Использовано выражение `${{ inputs.target_environment || 'testing' }}`.
- Добавлен вывод выбранного окружения в логи.

### Практика 4. Проверка изменений в GitHub Actions
- Изменения workflow отправлены в GitHub.
- Проверен успешный запуск CI после обновления конфигурации.

### Практика 5. Проверка автоматического запуска
- Запуск GitHub Actions #30 завершился успешно.
- Задания `basic-check` и `validation` прошли.
- В логах подтверждено: `Selected target environment: testing`.

### Практика 6. Ручной запуск с параметром staging
- Workflow запущен вручную с выбором `staging`.
- Запуск GitHub Actions #31 завершился успешно.
- Задания `basic-check` и `validation` прошли.
- В логах подтверждено: `Selected target environment: staging`.

## Изменённые файлы
- `.github/workflows/first-ci.yml` — добавлены параметры ручного запуска и передача целевого окружения.
- `docker/day34.md` — журнал обучения.

## Итог дня
- Освоен `workflow_dispatch` с пользовательскими параметрами.
- Изучены тип `choice`, `default` и контекст `inputs`.
- Проверена передача параметров в переменные окружения job.
- Подтверждена работа автоматического и ручного запусков CI.
