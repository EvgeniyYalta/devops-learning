# День 30 — GitHub Actions: отчёты и артефакты CI

## Цель
Научиться автоматически формировать отчёты о проверках Bash-скриптов и сохранять их как артефакты GitHub Actions.

### Практика 1. Проверка существующего CI
- Проверили состояние Git-репозитория.
- Изучили структуру workflow `first-ci.yml`.
- Убедились в наличии Bash-скрипта `ci/scripts/file_check.sh`.
- Проверили отсутствие каталога `ci/reports`.

### Практика 2. Создание генератора отчётов
- Создали каталог `ci/reports`.
- Создали скрипт `ci/scripts/generate_report.sh`.
- Проверили синтаксис и выполнили скрипт.
- Получили отчёт `ci/reports/test-report.txt`.

### Практика 3. Подключение отчёта к CI
- Добавили шаг `Generate CI report` в GitHub Actions.
- Добавили шаг `Upload CI report`.
- Использовали `actions/upload-artifact@v4`.
- Настроили сохранение отчёта под именем `bash-test-report`.

### Практика 4. Проверка GitHub Actions
- Отправили изменения в GitHub.
- Проверили запуск workflow `Day 30: Add CI report artifact`.
- Оба задания `basic-check` и `validation` завершились успешно.
- GitHub Actions сформировал один артефакт `bash-test-report`.

### Практика 5. Проверка содержимого артефакта
- Скачали артефакт из GitHub Actions.
- Открыли файл `test-report.txt`.
- Подтвердили результаты `Bash syntax check: PASSED` и `Report generation: SUCCESS`.

### Практика 6. Итоговая проверка
- Проверили историю коммитов и состояние Git.
- Подтвердили наличие скриптов и локального отчёта.
- Убедились, что отчёт доступен как артефакт GitHub Actions.

## Созданные файлы
- `ci/scripts/generate_report.sh` — генератор отчётов.
- `ci/reports/test-report.txt` — локальный отчёт.
- `docker/day30.md` — журнал обучения.

## Изменённые файлы
- `.github/workflows/first-ci.yml` — добавлены генерация и загрузка артефакта.

## Итог дня
Освоили создание отчётов в CI и публикацию артефактов через GitHub Actions. Проверили полный цикл: выполнение тестов, формирование отчёта, загрузка артефакта и скачивание результата.
