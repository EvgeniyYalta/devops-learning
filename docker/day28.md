# День 28 — GitHub Actions: зависимости между jobs

## Цель
Научиться создавать зависимые задания в GitHub Actions, управлять порядком их выполнения и проверять поведение CI при ошибках.

### Практика 1. Проверка существующего workflow
- Проверили состояние репозитория и последний коммит.
- Изучили `.github/workflows/first-ci.yml`.
- Убедились, что существующий job `basic-check` работает и репозиторий готов к изменениям.

### Практика 2. Создание зависимого job
- Добавили второй job `validation`.
- Использовали `needs: basic-check` для определения зависимости.
- Настроили выполнение на `ubuntu-latest`.
- Создали коммит `b014fb4` и отправили изменения в GitHub.

### Практика 3. Проверка успешного выполнения
- Проверили запуск GitHub Actions после изменения workflow.
- `basic-check` завершился успешно.
- `validation` выполнился после успешного завершения `basic-check`.
- Общий результат workflow — Success.

### Практика 4. Проверка зависимости при ошибке
- Намеренно изменили `exit 0` на `exit 1` в шаге `Verify CI recovery`.
- Создали коммит `b14ae22`.
- Проверили результат GitHub Actions:
  - `basic-check` — Failure.
  - `validation` — Skipped.
- Подтвердили, что зависимый job не запускается при ошибке основного.

### Практика 5. Восстановление CI
- Вернули `exit 0` в `Verify CI recovery`.
- Создали коммит `cfc4971`.
- Проверили повторный запуск:
  - `basic-check` — Success.
  - `validation` — Success.
- Подтвердили восстановление рабочего CI.

### Практика 6. Итоговая проверка
- Проверили `git status` и историю последних коммитов.
- Убедились, что ветка `main` синхронизирована с `origin/main`.
- Проверили зависимость `needs: basic-check`.
- Подтвердили, что `Verify CI recovery` завершается с кодом `0`.

## Изменённые и созданные файлы
- `.github/workflows/first-ci.yml` — добавлен зависимый job `validation`, проверены сценарии ошибки и восстановления.
- `docker/day28.md` — журнал практик дня.

## Итог дня
Освоили зависимости между jobs в GitHub Actions с помощью `needs`. Проверили успешное выполнение, пропуск зависимого задания при ошибке и восстановление CI. Финальная конфигурация работает успешно.
