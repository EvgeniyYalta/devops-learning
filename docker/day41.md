# День 41 — GitHub Actions: управление выполнением шагов

## Цель
Изучить условие `always()` в GitHub Actions, проверить выполнение завершающего шага после ошибки и восстановить успешную работу CI.

### Практика 1. Проверка существующего workflow
- Проверена структура `.github/workflows/first-ci.yml`.
- Изучены задания `basic-check`, `validation`, `staging-check` и `matrix-check`.
- Проверены зависимости `needs`, условия `if` и настройка `fail-fast: false`.
- Установлено, что шаги `Report success` и `Report failure` уже используют условия `success()` и `failure()`.

**Результат:** определено место для применения `always()` без создания дублирующих шагов.

### Практика 2. Добавление always()
- В существующий шаг `Finish` добавлено условие `if: ${{ always() }}`.
- Сообщение изменено на `CI pipeline finished`.
- Выполнена проверка изменений через `git diff --check` и `git diff`.
- Изменение отправлено в GitHub, коммит `3bb810a`.
- Запуск GitHub Actions #57 завершился успешно.
- В логах `Finish` подтверждено сообщение `CI pipeline finished`.

**Результат:** завершающий шаг успешно выполняется в обычном сценарии.

### Практика 3. Проверка always() при ошибке
- В шаге `Verify CI recovery` временно изменён код завершения с `exit 0` на `exit 1`.
- Изменение отправлено в GitHub.
- Запуск GitHub Actions #58 завершился с ожидаемой ошибкой.
- `Verify CI recovery` — Failure.
- `Report success` — Skipped.
- `Report failure` — Success.
- `Finish` — Success.
- Все три задания матрицы завершились успешно.

**Результат:** подтверждено, что `always()` позволяет выполнить завершающий шаг даже после ошибки предыдущего шага.

### Практика 4. Восстановление CI
- В шаге `Verify CI recovery` восстановлен `exit 0`.
- Проверены изменения и форматирование YAML.
- Создан коммит `16af090`.
- Изменения отправлены в GitHub.
- Подтверждено чистое состояние Git и синхронизация с `origin/main`.
- Запуск GitHub Actions #59 завершился успешно за 19 секунд.
- Успешно выполнились `basic-check`, `validation` и три задания матрицы.
- `staging-check` ожидаемо пропущен.
- Создан артефакт отчёта.

**Результат:** CI восстановлен и работает успешно.

## Изменённые файлы
- `.github/workflows/first-ci.yml` — добавлено условие `always()` к существующему шагу `Finish`.

## Итог дня
- Изучено назначение `always()` в GitHub Actions.
- Закреплено различие между `success()`, `failure()` и `always()`.
- Проверено выполнение шагов после намеренной ошибки.
- Подтверждено, что `always()` не скрывает ошибку задания.
- Выполнено восстановление CI после теста.
- Все изменения workflow сохранены в GitHub.
