# День 44 — GitHub Actions: concurrency

## Цель дня
Освоить управление параллельными запусками CI и автоматическую отмену устаревших workflow.

### Практика 1. Проверка существующего workflow
Проверена конфигурация first-ci.yml, состояние репозитория и отсутствие настроек concurrency.

### Практика 2. Настройка concurrency
Добавлена группа concurrency на уровне workflow.
Для формирования группы использованы github.workflow и github.ref.
Проверен успешный запуск CI после изменения конфигурации.

### Практика 3. Настройка cancel-in-progress
Добавлен параметр cancel-in-progress: true.
Настроена автоматическая отмена предыдущего запуска при поступлении нового запуска в той же группе.
Проверена работоспособность CI.

### Практика 4. Проверка отмены запусков
Добавлена временная задержка sleep 90 в шаг Verify CI recovery.
Созданы пустые коммиты с помощью git commit --allow-empty для запуска нескольких workflow.
Проверено автоматическое завершение устаревших запусков.
Запуски #71 и #72 отменены, запуск #73 завершился успешно.

### Практика 5. Восстановление CI
Удалена тестовая задержка sleep 90.
Восстановлен штатный шаг Verify CI recovery.
Настройки concurrency и cancel-in-progress сохранены.
Запуск #74 завершился успешно за 13 секунд.

## Итог дня
- Освоен механизм concurrency в GitHub Actions.
- Изучено формирование групп параллельных запусков.
- Настроена автоматическая отмена устаревших workflow.
- Проверено поведение CI при нескольких последовательных push.
- Восстановлена штатная работа CI.

## Созданные и изменённые файлы
- .github/workflows/first-ci.yml — добавлено управление параллельными запусками.
- docker/day44.md — документация выполненных практик.

## Результат
CI работает штатно. Устаревшие запуски автоматически отменяются при поступлении нового запуска в той же группе.
