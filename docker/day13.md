# День 13 — Docker Compose

## Цель
Освоить Docker Compose: описание нескольких сервисов, запуск и управление проектом, взаимодействие контейнеров через Compose-сеть, проверку конфигурации, логи, жизненный цикл сервисов и переменные окружения.

## Практики

### 1. Проверка Docker Compose
Проверена установленная версия Docker Compose: v5.5.1.

### 2. Создание рабочего каталога
Создан каталог `~/docker-lab/compose-practice` для практики Docker Compose.

### 3. Проверка рабочего каталога
Подтвержден текущий путь командой `pwd`.

### 4. Первый compose.yaml
Создан Compose-файл с сервисом `web` на базе `nginx:latest` и публикацией порта `8083:80`.

### 5. Проверка конфигурации
Командой `docker compose config` проверена и нормализована Compose-конфигурация.

### 6. Запуск проекта
Проект запущен через `docker compose up -d`.

### 7. Проверка сервиса
Командой `docker compose ps` подтверждена работа контейнера `web` и публикация порта `8083`.

### 8. Проверка HTTP
Через `curl http://localhost:8083` подтвержден успешный ответ стандартной страницы Nginx.

### 9. Просмотр логов
Командой `docker compose logs web` проверен запуск Nginx и HTTP-запрос с кодом `200`.

### 10. Остановка сервиса
Сервис `web` остановлен через `docker compose stop web`.

### 11. Запуск сервиса
Остановленный `web` повторно запущен через `docker compose start web`.

### 12. Перезапуск сервиса
Проверен `docker compose restart web`.

### 13. Проверка состояния
Командой `docker compose ps` подтверждено рабочее состояние `web`.

### 14. Удаление проекта
Командой `docker compose down` контейнер и Compose-сеть проекта удалены.

### 15. Добавление второго сервиса
В `compose.yaml` добавлен сервис `client` на базе `busybox:1.36` с командой `sleep 3600`.

### 16. Проверка конфигурации двух сервисов
Через `docker compose config` проверено наличие `web` и `client` в общей Compose-сети.

### 17. Запуск двух сервисов
Проект запущен через `docker compose up -d`; созданы сеть и оба контейнера.

### 18. Проверка двух сервисов
`docker compose ps` подтвердил работу `web` и `client`.

### 19. Проверка жизненного цикла client
Проверено состояние `client` после завершения заданной команды через `docker compose ps -a`; получен `Exited (0)`.

### 20. Пересоздание client
Сервис `client` пересоздан через `docker compose up -d --force-recreate client`.

### 21. Взаимодействие сервисов
Из `client` выполнен запрос к `web` по имени сервиса. Получена HTML-страница Nginx.

### 22. Проверка DNS и сети
Через `nslookup web` подтверждено разрешение имени `web` в `172.18.0.2`. Через `docker network inspect compose-practice_default` проверены сеть `172.18.0.0/16`, gateway `172.18.0.1` и подключенные контейнеры.

### 23. Переменная окружения Compose
В сервис `client` добавлена переменная `APP_ENV`. Проверена её передача через Compose-конфигурацию.

### 24. .env и подстановка переменной
Создан `.env` со значением `APP_ENV=testing`. В `compose.yaml` настроена подстановка `${APP_ENV}`. После `docker compose config`, пересоздания `client` и проверки внутри контейнера получено `testing`.

## Итог дня
Освоен практический workflow Docker Compose: создание проекта, описание нескольких сервисов, проверка конфигурации, запуск, остановка, запуск и перезапуск сервисов, просмотр логов, удаление проекта, взаимодействие контейнеров через Compose-сеть, внутреннее DNS-разрешение и передача переменных через `.env`.
