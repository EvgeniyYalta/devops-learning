# День 22 — Docker: диагностика и безопасная очистка

## Цель

Научиться диагностировать состояние Docker Engine, проверять остановленные контейнеры, анализировать логи и использование дискового пространства, безопасно очищать ненужные ресурсы без потери учебных данных.

## Практика 1. Проверка состояния Docker

- Проверили версию Docker Engine и состояние контейнеров.
- Установили, что Docker работает, но запущенных контейнеров нет.
- Проверили количество остановленных контейнеров и использование дискового пространства.

## Практика 2. Диагностика остановленных контейнеров

- Изучили состояние контейнеров через `docker inspect`.
- Проверили `Status`, `ExitCode`, `OOMKilled` и сообщения об ошибках.
- Разобрали различия между кодами завершения 0 и 255.
- Установили, что `day21-nginx` завершился с кодом 0.

## Практика 3. Анализ логов

- Изучили `docker logs --tail` и `docker logs --timestamps`.
- Проверили логи backend-контейнера дня 19.
- Выполнили поиск сообщений `error`, `failed`, `fatal`, `panic`.
- Проверили сообщения о штатном завершении Nginx.

## Практика 4. Анализ дискового пространства

- Использовали `docker system df` и `docker system df -v`.
- Изучили размеры образов, контейнеров, volumes и Build Cache.
- Проверили, какие образы используются существующими контейнерами.
- Определили ресурсы, потенциально доступные для очистки.

## Практика 5. Удаление остановленного контейнера

- Проверили состояние `ubuntu-test`.
- Удалили только выбранный тестовый контейнер.
- Убедились, что количество контейнеров уменьшилось с 16 до 15.
- Сохранили остальные контейнеры и Docker volumes.

## Практика 6. Выборочная очистка образов

- Проверили список Docker images.
- Удалили неиспользуемый образ `ubuntu:24.04`.
- Количество образов уменьшилось с 11 до 10.
- Размер образов уменьшился с 779,6 до 660,2 МБ.
- Остальные учебные образы сохранены.

## Практика 7. Анализ и очистка Build Cache

- Проверили Build Cache через `docker buildx du`.
- Изучили параметры `docker builder prune`.
- Выполнили стандартную очистку без `-a`.
- Установили, что объём кэша остался 99,73 МБ.
- Принудительную очистку не применяли.

## Практика 8. Итоговая диагностика

- Проверили состояние Docker Engine — `active`.
- Подтвердили отсутствие запущенных контейнеров.
- Проверили сохранность 15 контейнеров и 10 образов.
- Убедились, что named volume `day20-compose_web-data` сохранён.
- Повторно проверили использование дискового пространства.

## Итог дня

Освоены диагностика контейнеров, анализ логов, проверка дискового пространства Docker, безопасное удаление отдельных контейнеров и образов, анализ Build Cache.

**Результат:** Docker Engine работает, ненужный тестовый контейнер и образ Ubuntu удалены, остальные учебные ресурсы сохранены. Финальная проверка выполнена успешно.
