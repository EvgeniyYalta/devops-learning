# День 26 — GitHub Actions: диагностика ошибок CI

## Цель
Научиться воспроизводить ошибки CI, анализировать журналы GitHub Actions и восстанавливать успешное выполнение pipeline.

### Практика 1. Проверка существующего workflow
- Проверили состояние Git-репозитория.
- Изучили `.github/workflows/first-ci.yml`.
- Убедились, что workflow содержит проверки окружения, Docker и конфигурации Docker Compose.

### Практика 2. Имитация ошибки CI
- Добавили шаг `Simulate CI failure`.
- Использовали `echo` для диагностического сообщения и `exit 1` для намеренного завершения с ошибкой.
- Создали коммит `af6c1c1` и отправили изменения на GitHub.

### Практика 3. Диагностика сбоя
- Открыли неуспешный запуск GitHub Actions.
- Нашли ошибку `Process completed with exit code 1`.
- Установили, что шаг `Finish` был пропущен.
- Убедились, что служебная очистка `Post Checkout repository` выполнилась.

### Практика 4. Исправление workflow
- Заменили `Simulate CI failure` на `Verify CI recovery`.
- Заменили `exit 1` на `exit 0`.
- Проверили изменения командами `git diff` и `git diff --check`.

### Практика 5. Повторный запуск CI
- Создали коммит `1e5af21`.
- Отправили исправления в `main`.
- Получили успешный запуск GitHub Actions со статусом `Success`.

### Практика 6. Итоговая проверка
- Проверили историю коммитов через `git log`.
- Убедились, что локальная ветка синхронизирована с GitHub.
- Проверили чистоту рабочего дерева командой `git status`.

## Изменённые и созданные файлы
- `.github/workflows/first-ci.yml` — добавлена и затем исправлена проверка CI.
- `docker/day26.md` — журнал обучения.

## Итог дня
Изучили поведение GitHub Actions при ошибке команды, влияние кода завершения на статус pipeline, пропуск последующих шагов и восстановление успешного CI.

**Результат:** намеренный сбой воспроизведён, причина установлена, workflow исправлен и успешно запущен повторно.
