# День 20 — Docker Compose: Volumes, Bind Mounts и Backup

## Цель

Изучить хранение постоянных данных в Docker Compose, отличия named volumes от bind mounts, защиту файлов от записи, жизненный цикл томов и резервное копирование с восстановлением.

## Практика 1. Проверка окружения

- Проверены Docker Engine 29.8.1 и Docker Compose 5.5.1.
- Проверено отсутствие запущенных контейнеров и существующих томов.
- Установлено, что порт 8086 свободен.

## Практика 2. Подготовка проекта

- Создан каталог `~/docker-lab/day20-compose`.
- Подготовлена директория `nginx`.
- Создан файл `compose.yaml` для запуска Nginx с named volume.
- Проверена конфигурация через `docker compose config`.

## Практика 3. Запуск Nginx с named volume

- Запущен Compose-проект.
- Создан том `day20-compose_web-data`.
- Проверена работа Nginx на порту 8086.
- Получен HTTP-ответ `200 OK`.

## Практика 4. Запись данных в named volume

- Создан тестовый `index.html` внутри контейнера.
- Проверено содержимое файла.
- Через HTTP получена страница `Day 20 - Docker Volume Test`.

## Практика 5. Сохранность данных

- Выполнен `docker compose down` без удаления тома.
- Проверено сохранение named volume.
- Контейнер создан повторно через `docker compose up -d`.
- Подтверждено сохранение тестовой страницы после пересоздания контейнера.

## Практика 6. Bind mount и read-only

- Создан каталог `site` и файл `site/index.html`.
- Запущен отдельный контейнер `day20-bind-test` на порту 8087.
- Подключён bind mount в режиме `readonly`.
- Изменение файла на хосте сразу отобразилось внутри контейнера и через HTTP.
- Попытка записи из контейнера завершилась ошибкой `Read-only file system`, exit code 2.

## Практика 7. Очистка тестового контейнера

- Остановлен и удалён контейнер `day20-bind-test`.
- Подтверждено отсутствие контейнера в `docker ps -a`.
- Проверено, что основной Compose-проект и named volume остались доступны.

## Практика 8. Жизненный цикл named volume

- Проверено, что `docker compose down` сохраняет named volume.
- Данные успешно прочитаны временным контейнером Alpine.
- После повторного запуска Compose тестовая страница сохранилась.
- Выполнен `docker compose down -v`.
- Подтверждено удаление контейнера, сети и named volume.
- Проверено, что порт 8086 недоступен, `curl` завершился с кодом 7.

## Практика 9. Повторное создание тома

- Выполнен `docker compose up -d`.
- Docker создал новый named volume с прежним именем.
- Вместо пользовательской страницы появилась стандартная страница Nginx.
- Подтверждено, что удалённые данные автоматически не восстанавливаются.

## Практика 10. Backup и Restore

- Создан каталог `backups`.
- Подготовлена страница `Day 20 - Backup Test`.
- Создан архив `backups/web-data-backup.tar.gz` с помощью Alpine и `tar`.
- Проверено содержимое архива: `index.html` и `50x.html`.
- Проверка `gzip -t` завершилась с кодом 0.
- Создан отдельный том `day20-restore-test`.
- Архив распакован в тестовый том.
- Восстановленный `index.html` успешно прочитан.
- Временный том удалён.
- Рабочий named volume и резервная копия сохранены.
- Nginx продолжает возвращать тестовую страницу через порт 8086.

## Созданные файлы

- `~/docker-lab/day20-compose/compose.yaml`
- `~/docker-lab/day20-compose/site/index.html`
- `~/docker-lab/day20-compose/backups/web-data-backup.tar.gz`
- `~/devops-learning/docker/day20.md`

## Итог дня

Освоены named volumes и bind mounts в Docker Compose, сохранение данных при пересоздании контейнеров, ограничения `readonly`, различия между `docker compose down` и `docker compose down -v`, резервное копирование и восстановление данных.

**Результат:** рабочий Nginx доступен на порту 8086, named volume `day20-compose_web-data` сохранён, резервная копия создана и успешно проверена восстановлением в отдельный том.
